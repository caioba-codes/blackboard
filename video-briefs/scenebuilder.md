# Scene builder brief · one assigned module

Role: implement one assigned `scenes/<module>.js` in an external video project. **Required actual model: Claude Opus 5.5. Use the explicit effort in `project.json` (`high` recommended).** The parent gives the project path and exact module. Work only on that module and its QA stills; do not edit the lesson, script, timeline, anchors, shared engine/style, or another builder's scenes. The script and measured timeline are the contract. No further GO is needed.

Read the whole `engine.js`, `style.css`, `script.json`, `timeline.json`, `anchors.json`, mathcheck output, and the portable runtime README. Use `SPLIT.json` to identify your scenes; module keys are basenames matching `[A-Za-z0-9_-]+` and never include `.js`. Build pure time-based, deterministic frames using the runtime's scene API; cue starts and subtitle chunks supply actual reveal timing. Keep text and math readable at 1920×1080, inside the content bounds and above subtitles. Preserve the prior line of a derivation when adding the next one unless layout requires a deliberate transition. Show a concrete physical situation before formula notation. Pace the screen with the narration (`VIDEO.md`, Pacing and practice): build circuits and derivations one visible step at a time, show each intermediate value when it is spoken, and never put a symbol, label or gate on screen before the narration has said what it means. Use appropriate motion only when it explains mechanism.

For every scene: check numerical labels against independent math, angles against actual geometry, arrows against sign and direction, curves against equations, and units. A frozen moving object needs an explicit snapshot state with its true velocity. In question scenes, show the whole prompt and choices, then countdown during the `think` cue. No answer, green key, worked line, or trap explanation may appear before the pause ends. Reveal the answer at the measured answer cue; sync each distractor reason to the spoken option. If several questions occupy one scene, use separate countdown/reveal state for each anchor gate.

Run `node --check scenes/<module>.js`, capture every assigned scene with the runtime's exact `node capture.mjs scene <scene-id> 2` command, inspect **all** stills, and fix clipped, overlapping, empty, premature, or inaccurate frames. Also capture the instant just before and after each `think` end, and around each answer sentence. Re-capture after changes. Report the actual commands and output, scenes built, visual/math/reveal fixes, and unresolved issues. The parent records model identity from host runtime metadata; do not self-certify it.
