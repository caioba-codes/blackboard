1. Read the entire current lesson, its sources, figures, check-ins, MCQs, quiz, and next link. 2. Write `mathcheck.py` that independently computes every worked numeric result, practice answer, MCQ key and plausible distractor. Run it and include actual output. Check units, significant figures, geometry, and sign conventions. Do not use the script's claimed answer as the oracle.
3. Write `script.json` with title, subtitle, voice, chapters, and ordered scenes, each with `id`, `chapter`, concrete `visual`, and ordered `cues`. Use unique cue IDs within each scene. Use the lesson’s language and warm, short, conversational sentences that follow **Tone** in `TEMPLATES.md` (a listener cannot reread, so keep each subject next to its verb, keep "that" and "of", and split long sentences); there is no length cap or target (about 135 spoken words per minute is only for estimating runtime). Follow **Pacing and practice** in `VIDEO.md`: each concept says what it is and why it is needed, then builds one visible step at a time; define every symbol, gate and term before it appears; narrate every intermediate value of every worked example; one bridge sentence between concepts; cover every lesson practice item (all check-ins, checkpoint MCQs, practice-exam parts, quiz) as a pause-and-try segment followed by the full step-by-step solution, after confirming each item is an official course problem (send any non-official item back for replacement first). Write spoken math in words rather than LaTeX. Give chapter transitions their own clear visual treatment and allow 8–20 seconds for each think pause (longer for multi-part work). Start with a concrete phenomenon or question: show what changes and why, then introduce variables and formulas. Teach enough that a student could learn from the video alone. Cover all lesson teaching in source order, including prerequisites, examples, check-ins, MCQs, final quiz, figures and interactive mechanisms. Preserve scope and meaning. One derivation step per reveal with the reason shown beside it. Give each question a distinct `thinkN` pause and first spoken answer cue; name every wrong option and explain its actual mistake. Hide answer visuals through the end of the pause.
4. Write `anchors.json` as the script is planned. Each segment links one named script cue span to a **nonblank exact lesson source line** and optional board-verified step. Use `null` for check-ins or uncertain row mapping; the board groups some aligned rows and counts prose separately. Cover every scene from its start to end in order. Multiple questions in one scene get separate segments and practice gates. See `VIDEO.md` for schema. Do not infer source lines later from a rendered video or create guessed times.

Write `SPLIT.json` mapping local basenames such as `intro`, `chapter1`, `quiz` to each scene exactly once, in order, based on measured durations and balanced builder scope. Keys match `[A-Za-z0-9_-]+` and never include `.js`; the runtime loads `scenes/<key>.js`. Do not hardcode chapter IDs in shared code. Run `python3 /absolute/path/to/blackboard/bin/video_pipeline.py build-map --project "$PROJECT"` and `check` to see remaining work.
